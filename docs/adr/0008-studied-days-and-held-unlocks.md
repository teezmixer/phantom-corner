# 0008 — Studied days are their own list; unlocks are held until a location ships

- **Date:** 2026-11-23
- **Status:** accepted (spec §3.4 PROPOSED; the numbers and look are Tier 3, see D-31)
- **Context:** The calendar needs the date of each studied day, but the event log carries no timestamps (D-24), and Knowledge is a fold over that log. The spec also wants an unlock to wait when a player reaches a location that has not shipped (§3.4).
- **Decision:**
  - **Calendar:** a separate list `studiedDays: { day: "YYYY-MM-DD", style }[]` (schema 4), kept in date order, capped at 3660 days (oldest dates go first). The key is the **local** date, because "today" is the player's day. A session is stamped on the day it really ended (a finished session: its end time, even if the tab only noticed later or was closed), by one function (`recordSession`) used by both the reducer and the load path. A day keeps its first stamp, and each stamp keeps the design current when it was made. On load the list is repaired (bad entries dropped, trimmed, sorted); it never costs the whole save.
  - **Held unlocks:** `unlockState(level, locations, shipped)` returns what can be entered and what is held. `SHIPPED_LOCATIONS` in `content/progression.ts` is the only list to edit when a location ships. A held location is never in `unlocked`.
  - **Level gifts:** a reward table (`LEVEL_REWARDS`), with wording in `content/copy`. Level-ups announce the gift after the level. Notices for a session that finished while the tab was closed are worked out at load against the log without that session, and wait in the banner queue until the player enters.
- **Rejected:** putting `at` timestamps on every event now (a bigger change that D-24 plans for the sync work in M11, and it would still not date sessions from before); deriving the calendar from event order (no dates); a shipped flag inside each location manifest (it would put a release decision in a content file that should only describe the place).
- **Consequences:** sessions recorded before schema 4 cannot be stamped (the calendar starts empty for existing players). When M11 adds `id` and `at` to events, `studiedDays` stays valid as the local record. A location that ships in a later build is not announced by the banner queue (it changes nothing in the player's own log); its IM arrives with the thread system (M8). A session stopped after a long pause is stamped on the day Stop was pressed.
