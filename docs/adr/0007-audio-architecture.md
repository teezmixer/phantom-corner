# 0007 — Audio: a visible YouTube TV behind an interface, plus synthesised Web Audio buses

- **Date:** 2026-11-22
- **Status:** accepted (spec §4.8, §3.9, CHANGE-2 PROPOSED; visible-player rules are YouTube's published terms)
- **Context:** Music must come from YouTube embeds (no hosted music), under rules that forbid hiding, covering or auto-starting the player. Interface sounds and ambience need real mixing, but no audio files exist and none may be taken from the game.
- **Decision:**
  - **Music** is one YouTube player in a 200×200 box that is never scaled, covered or hidden (Hide UI keeps it; screens leave it a gutter; it sits above their scrim). Our controls sit *beside* the video, never over it. The player talks to the app only through `MusicBackend` (`audio/music/youtube.ts`); a pure reducer (`audio/music/controller.ts`) holds every rule: playback starts only from PLAY/NEXT/PREV (user actions); error codes 2/5/100/101/150/153 skip the track silently; all failed → unavailable; a play that never starts within 5 s → blocked; a new playlist (travel) stops playback. The IFrame script is injected when the TV mounts, which is after the user has entered. Volume is the player's own (`setVolume`), as the spec says it is the only mixing control.
  - **Interface sounds and ambience** go through Web Audio: `AudioEngine` creates its `AudioContext` only from a user gesture (the splash click, or the first pointer/key press in demo and dev modes). Sounds are *data* (`audio/sfx.ts`, oscillator notes) and ambience is filtered noise (`audio/ambience.ts`); no audio files exist. Interface sounds halve while a session runs; the completion fanfare is the loudest sound. Which sound plays for which state change is a pure function (`audio/triggers.ts`).
  - **Settings:** three bus volumes and a per-layer ambience mix are saved in schema 2 (the first migration; ADR 0005).
- **Rejected:** a hidden or audio-only YouTube player (forbidden, spec CHANGE-2); routing YouTube audio through Web Audio (impossible cross-origin); sound files from the game or the web (rights); autoplaying the next location's music after travel (the user's last click is too far from the play request; see D-26); a `<audio>` element with hosted tracks (hosted music is out of scope).
- **Hardening after review (M4):** the player box is 204 px (200 + the 2 px border each side) so the video's *inner* area is a full 200×200 and YouTube's watermark is not clipped; YouTube's default chrome stays (`controls` is not overridden) and the privacy-enhanced host `youtube-nocookie.com` is used; the player's own state is the truth (if the user clicks the video itself the caption follows); a track that ends advances only if it was playing; the YouTube script and player wait for the user's first gesture (so demo mode contacts nothing at load); a failed script can be retried by pressing play, with a 10 s ready-timeout and an abort signal so StrictMode builds one iframe; "blocked" is only reported once a player exists; audio listens for every gesture until it runs and never queues sounds on a suspended context; ambience fades out instead of clicking off; the caption steps aside while a screen is open; on a short window the TV sits just below the todo widget and the location sign gives way (the player is never the thing covered).
- **Verified in a real browser (2026-11-22):** the app on the dev server, with the real IFrame API, loaded the "Beneath the Mask" Topic upload at 200×200 with YouTube's own chrome, played from our Play button, and next/previous moved through all three tracks with no console errors. Doing this found a real bug the fake player had hidden (a transient pause event when switching videos), now fixed and covered. Opening the embed URL as a top-level page shows Error 153 because no referrer is sent; that is expected and not what the app does. **Not verified:** playback in other countries or on other devices — an oEmbed 200 and one real run do not prove availability everywhere, which is what the skip rule and the planned weekly check are for.
- **Consequences:** tests use a stubbed `YT` and a probed `AudioContext`, so they never touch the network or need speakers; the audio code is verifiable but *how it sounds* is not — every tone is a placeholder for Ares's sound design (D-13, D-25). Embedding can break any time (a video removed or embedding turned off): the skip rule and the weekly oEmbed check (planned for M10) are the defence. A Content Security Policy (M10) must allow scripts from `https://www.youtube.com` and `https://s.ytimg.com`, and frames and images from `https://www.youtube-nocookie.com`, `https://i.ytimg.com`.
